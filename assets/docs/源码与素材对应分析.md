# 源码与素材对应分析

分析对象仅为上传压缩包中的代码。下面的文件路径和行号以该包版本为准；其中多个 TSX/CSS 文件把大量内容压在同一行，行号定位后还需按组件名搜索。

## 1. 原页面不需要被改造成整张“游戏海报”

`docs/DESIGN.md` 明确以可操作的魔典为核心：暗色背景、中央座位环、右侧任务/玩家详情；角色采用文字徽章与 Lucide 线条图标。`src/styles/app.css:2` 定义背景 `#111315`、面板 `#191c20`、操作红 `#a74248`、强调金 `#c6ad74`、善良蓝 `#649ddd` 和邪恶粉红 `#d26e76`。

因此素材适合增强入口与辨识，而不是替代文字、表单、计票控件。生成图集中的整套有字按钮不作为正式组件切图交付：这样不会将错误文案、固定像素字形或不可访问的按钮状态引入应用。

## 2. 首页：小标识和剧本缩略图优先

`src/App.tsx` 中品牌区使用 `.brand-mark` 和 `<BookOpen>`；`src/features/Home.tsx` 使用 `.home-heading`、`.script-preview` 展示首页标题和当前选中剧本。

圆形钟楼标识适合替换品牌区的小书本图标。`town-night-red` 等小场景适合给 `.script-preview` 添加 80 × 48 px 缩略图。两张有字主视觉仅作标题图参考，不应该把现有 HTML 的“血染钟楼”标题再次叠上去。

现有场景不是高清首页横幅，因此接入示例不默认把它们设置成页面全屏背景。

## 3. 角色素材：最直接的接入点

`src/components/ui.tsx:16` 的 `RoleToken` 目前显示角色名称首字，并根据阵营/旅行者切换颜色；它被角色详情、剧本目录、配置区和玩家身份展示等位置调用。样式中普通徽章为 64 px、小徽章为 38 px，玩家翻牌后的徽章为 90 px。

本包针对 `supabase/functions/_shared/catalog.ts` 的 `tb` 列表建立了 22 个 ID 映射。图案是当前生成素材中挑选出的象征，而不是官方图片。例如管家使用侍酒杯、隐士使用提灯、红唇女郎使用玫瑰。仍然必须显示中文名称，不能假设玩家只看图便能准确认出角色。

有些图片不是圆盘图案：守鸦人、隐士、红唇女郎是透明插画。示例统一使用 `object-fit: contain`，不把角色图案强行拉伸。为控制清晰度，90 px 外框中的图画本身也不默认放大到 90 px。

`bmr`、`snv`、旅行者等不在专属 22 图覆盖内的角色，可使用类别默认图案；也可以选择不启用默认图案，继续显示首字。没有将 22 图说成全部角色库。

## 4. 身份卡：保密优先于装饰

`src/features/Player.tsx:16` 的 `.identity-card` 在 `revealed` 为真时才显示 `p.role`、`p.alignment`；组件还有失焦/页面切换遮挡，以及 30 秒后遮挡逻辑。

本包的 `identity-back` 是统一无字卡背。其作用是视觉背景，不能替代“查看我的身份”按钮，也不能按角色或真实阵营选择不同背面。

另外，角色实际身份与玩家展示身份不一定相同。接入时继续传现有代码的 `p.role`，不要改为从主持人数据寻找真实 `roleId`。可见性规则不能由图片文件名自行决定。

## 5. 魔典与公开城镇：不要泄露不该看的信息

`src/components/TownBoard.tsx` 负责座位环与列表布局，并接受 `phase`、`round`、`seats` 等显示数据。`Host.tsx:22` 的公开视图通过 `publicGame(g)` 生成公开数据；`Player.tsx` 的 `PublicTown` 也调用该座位组件。

当前素材中的白昼/月夜小场景可以放在阶段标题旁，但像素不足以作为整个座位环的高清底图。公开场景只跟随公开阶段；不应该因为隐藏角色、恶魔是否存活、醉毒状态等秘密变色或切换图片。

状态图标更适合放在现有状态文字旁。蓝太阳、红骷髅、毒滴、盾牌、沙漏、勾叉等不是规则判定逻辑；尤其毒、醉、保护与能力已用只在现有权限允许的区域显示。

## 6. 剧本工坊：ID 与封面的边界

`supabase/functions/_shared/catalog.ts:125–129` 给出三个基础剧本：`tb` 暗流涌动、`bmr` 黯月初升、`snv` 梦殒春宵。`src/features/Scripts.tsx:17` 的 `.library-item` 当前只有书本图标和文字，没有独立封面区。

本包提供的是**可复用小缩略图映射**，不是三张完整定制封面。`tb` 默认使用暗夜街景，`bmr` 默认使用钟楼特写，`snv` 默认使用紫色神秘纹章，自定义剧本使用卷轴。这是建议的视觉分类，不表示图案具有官方剧本含义。

`copyScript` 会给副本分配新 UUID，不能只靠副本 ID 决定封面。示例先识别基础 ID，再看已保留的 `meta.english`，无法识别时返回自定义缩略图。进一步定制应新增专门的封面配置字段，不要篡改游戏规则字段。

## 7. 这次不需要数据库变化

交付是静态图片与前端接入示例，不需要修改 Supabase 表结构、RLS 或后端函数。仅为了本轮图片而引入远程图片存储、带鉴权的图片 API 或实时同步协议，会增加不必要的复杂度。

`vite.config.ts` 将 `base` 配置为 `process.env.VITE_BASE_PATH || './'`。素材引用示例据此通过 `import.meta.env.BASE_URL` 拼接静态路径，而不是直接把图片写为 `/art/...`。这属于本包新增的接入示例，不是声称原代码已这样加载图片；部署到仓库子路径后的实际图片访问仍需检查。
