# 界面与组件约定

## 设计目标

界面以手机端说书人为主要场景，采用居中的单列工作区。视觉使用低对比羊皮纸底、深墨文字和酒红主操作色；装饰只用于建立氛围，不能遮挡信息或替代真实控件。

核心色值定义在 `src/styles/parchment.css`：

| 用途 | 色值 |
| --- | --- |
| 页面背景 | `#f2e8d3` |
| 面板背景 | `#faf4e7` |
| 正文墨色 | `#30271f` |
| 边框 | `#c9bba2` |
| 主操作 | `#782f3b` |
| 善良 | `#23608b` |
| 邪恶 | `#922f40` |

颜色不能单独承载角色类别、阵营、存活或操作状态；必须同时提供名称、图标或其他文字说明。

## 布局与导航

- 首页按“说书人”和“玩家”分流，只展示当前任务需要的表单。
- 对局内固定保留“魔典、夜晚、计票、记录、剧本”五个主入口。
- 手机端主导航固定在底部，并为安全区预留空间。
- 配板、魔典和公开城镇使用围桌一圈的顺时针座位，说书人位于中心；座位详情和复杂工具使用弹窗或底部面板。
- 常用动作直接显示，低频、高风险或配置型操作放入“更多”或折叠区域。
- 页面和弹窗必须允许长房间名、角色名和错误提示自然换行。

## 交互层级

- 主按钮只用于当前步骤的主要动作；普通按钮用于次要动作；危险按钮仅用于删除、结束或不可逆裁定。
- 触控控件通常不小于 44 px，主要输入和按钮采用 48 px 或更高的点击区域。
- 保存、提交和同步期间禁用重复操作，并显示明确状态。
- 删除存档、结束对局、替换设备绑定等操作必须先说明目标和后果。
- 网络结果不确定时保留原操作 ID，通过“安全重试”确认结果，不能直接创建新的同类操作。

## 可访问性

- 所有图标按钮提供可读名称；装饰图片使用空替代文本。
- 表单控件有可见标签，键盘焦点清晰，错误信息靠近对应流程。
- 字体放大后仍应保持内容可访问，不以固定高度裁切正文。
- 动画遵循 `prefers-reduced-motion`，不使用闪烁或持续干扰操作的效果。
- 小屏验证至少覆盖窄屏、软键盘、底部安全区、长文本和弹窗滚动。

## 身份与隐私显示

- 身份卡背对所有玩家一致，图片 URL 和 DOM 不得提前包含真实角色信息。
- 玩家页只能使用个人投影中的展示身份，公开城镇只能使用公开投影。
- 真实身份、秘密标记和说书人笔记不得通过 CSS 隐藏后留在公开页面 DOM 中。
- 角色图片加载失败时保留文字或首字回退；角色名称始终可读。
- 自动遮挡用于减少误看，不应被描述为防截屏或防作弊机制。

样式入口和覆盖顺序位于 `src/main.tsx`。新增样式应优先复用现有变量和组件，避免继续堆叠互相覆盖的主题层。

## 房间与剧本工坊的统一规范

- 共用居中单列页面壳，最大宽度 520 px，手机左右留白 12 px、顶部 10 px，页标题 20 px。短页面不用装饰填高，长名单允许自然滚动，不以固定高度裁切内容。
- 工坊总览使用紧凑剧本信息栏；新建入口直接可见，先命名，再进入选角。作者与简介选填。
- 选角持续显示剧本名称、未保存状态、总角色数和各类别数量；已选名单直接按类别展示在选角页，无需点击展开；角色名称打开能力详情，旁边的 × 可直接移除。
- 镇民、外来者、爪牙、恶魔优先排列，旅行者、传奇、奇遇保留。剧本角色池不等于本局玩家或入袋角色。
- “完成选角”回到总览，只有“保存剧本”或“用此剧本开局”才持久化；长列表保留底部可达的完成操作。
