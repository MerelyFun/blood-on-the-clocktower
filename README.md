安装 Node.js 22.12+，建议 Node.js 24。解压后进入 `clocktower` 目录。

源码包已带 `dist`，可以直接运行：

```bash
node scripts/serve-dist.mjs
```

打开 `http://localhost:5173`。不需要安装依赖即可使用打包好的本机模式。不要直接双击 `dist/index.html`，浏览器会限制本地文件的模块加载。

需要修改源码时：

```bash
npm ci
npm run dev
```

生成新的发布文件：

```bash
npm run build
```

`npm run check` 执行类型检查、34 项自动测试与构建；`npm run typecheck:edge` 单独检查云端函数（首次下载固定版本 Deno）。`build` 本身只生成静态资源。

联机配置按 [Supabase 配置清单](docs/SUPABASE_SETUP.md) 操作。

## 部署到 GitHub

完整操作见 [GitHub 与 Supabase 部署指南](docs/DEPLOYMENT.md)。主要顺序：

1. 在专用 Supabase 项目中执行 `supabase/schema.sql`。
2. 配置 Auth、允许的网站来源，部署 `supabase/functions/game`。
3. 把本目录的内容推送到 GitHub 仓库根目录。
4. 填写前端公开配置，Pages 的 Source 选择 **GitHub Actions**。
5. 运行发布工作流。网站 URL 会显示在 Actions 的部署结果中。

也可以先不填写 Supabase 配置，发布本机主持版；联机入口会明确提示尚未配置。

## 使用顺序

1. 剧本工坊复制基础剧本，增删角色或导入自制 JSON，保存。
2. 创建本机或联机对局，设置人数。
3. 联机时玩家扫码申请，由说书人批准座位；也可发牌后开放加入，再锁定房间。
4. 随机生成候选配置，或逐座位指定真实与展示身份。核对酒鬼、疯子、外来者修正和恶魔伪装。
5. 确认固定分配还是随机分配，发身份，进入首夜。
6. 按夜间清单处理行动，标记实际状态，给指定玩家发送信息；不要把实际醉毒直接自动告知玩家。
7. 手动进入白天，选择公布哪些死亡 / 复活。记录提名与票数，确认是否处决、是否死亡。
8. 交替昼夜，由说书人确认最终胜负。选择复盘公开范围，导出存档。

详细边界见 [功能范围](docs/SCOPE.md) 与 [数据与权限设计](docs/ARCHITECTURE.md)。

## 目录

- `src/features`：剧本、开局、魔典、夜间、计票、玩家与记录页面。
- `src/components`：通用界面、身份令牌、城镇座位、登录。
- `src/lib`：联机请求、房间控制器、本机 IndexedDB、剧本同步。
- `supabase/functions/_shared`：前后端共用的类型、角色资料和命令引擎。
- `supabase/functions/game/index.ts`：验证身份、授权、事务提交入口。
- `supabase/schema.sql`：数据库表、RLS、显式权限、原子 RPC。
- `.github/workflows`：Pages 发布、手动 Supabase 函数发布。
- `dist`：本次构建的静态文件；由源码再次构建会覆盖。
