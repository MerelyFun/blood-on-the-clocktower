# 数据与权限设计

## 两种模式

本机模式用 IndexedDB 存储完整魔典，跨标签页更新通过 BroadcastChannel 提醒。操作在同一 IndexedDB 写事务中读取旧版本、执行引擎、保存新版本。浏览器数据属于说书人设备，供线下主持。

联机模式由 Supabase Auth 确定操作者，Edge Function 控制读写，Postgres 事务作为事实来源。前端与 Edge Function 复用 `_shared/engine.ts`，但联机用户无法让浏览器中的引擎替代服务端授权。

## 表与可见性

| 表 | 内容 | 客户端权限 |
| --- | --- | --- |
| `bt_rooms` | 房间名称、码、拥有者、锁定状态 | 活动成员只读 |
| `bt_members` | 用户绑定、角色、加入状态 | 本人可读自己的行；说书人可读本房间成员；客户端不可写 |
| `bt_games` | 完整魔典 JSON、乐观版本 | 仅说书人只读 |
| `bt_public` | 公开阶段、座位、生死、已公布事件和复盘 | 活动房间成员只读 |
| `bt_player_views` | 展示身份、展示阵营、个人私信和回执 | 当前座位绑定本人或说书人可读 |
| `bt_signals` | 公开 / 主持人 / 座位受众的随机刷新信号 | 按当前成员与座位过滤 |
| `bt_commands` | 已提交操作 ID | 无普通客户端权限 |
| `bt_scripts` | 用户剧本 | 所有者读写 |
| `bt_notes` | 玩家私人笔记 | 作者且仍为房间成员时读写；说书人无额外读取权 |
| `bt_private.join_limits` | 每用户每分钟的进房尝试计数 | 仅服务端 |

数据库没有用一个公开 JSON 承载完整魔典再让 UI 隐藏。玩家真实酒鬼字段、其他人的卡片、全部秘密标记和说书人笔记根本不会进入玩家的读取投影。

`publicGame` 不包含完整局面的版本号、更新时间、秘密事件数量或夜间行动对象。只在公开投影真正变化时写公共表和刷新信号。修改真实角色但不修改展示角色时，不增加玩家身份卡版本；发牌前，个人投影不会给出预分配的角色或阵营。

## 写入路径

1. 前端发命令类型、载荷、房间 ID、随机操作 UUID；说书人附带所看到的局面版本。
2. Edge Function 调用 `auth.getUser` 确认 JWT，读取数据库成员关系，不使用可编辑的 user metadata 判断角色。
3. 服务端加载完整状态，执行命令。玩家只可确认自己的卡片、阅读自己的消息、回复自己的选择请求。
4. `bt_commit_room` 锁住房间和状态，再核对操作者当前角色 / 座位、是否已提交、预期版本和座位占用。
5. 在同一事务里写完整状态、公开投影、逐座位投影、操作 ID 与必要的刷新信号。
6. 返回调用者有权读取的投影。并发玩家回复遇到版本冲突可在服务器重试；说书人命令冲突则刷新并重新确认。

服务端 RPC 的 execute 权限只授予 `service_role`。它们使用 SECURITY INVOKER；RLS 的少量成员检查 helper 放在未暴露的 `bt_private` schema，用显式 search_path 的 SECURITY DEFINER 避免策略递归。普通客户端没有 game 状态的写权限。

## 连接与撤权

Realtime 仅订阅小型刷新信号，不广播完整魔典或私信载荷。收到信号后重新鉴权读取，并在切回页面 / 网络恢复时刷新。可见页面每 10 秒补拉一次状态。

撤权 / 重绑与游戏提交持有同一个房间锁。被重绑的旧用户不能继续为旧座位提交操作。读取个人投影后再次核对成员状态；已经交付给设备的过去信息无法收回。

响应设置 no-store；没有缓存秘密 API 响应的 Service Worker。玩家身份在切出页面或 30 秒后从显示 DOM 中移除。说书人“公开视图”用独立公共组件替换工作台 DOM；Shift + Escape 可快速切换。

## 配置与内容边界

角色池、入袋角色实例、玩家展示身份是不同字段。座位拥有独立 UUID，换座位只换 index，身份、标记、账号绑定和信息仍跟随 seat ID。

生死分成真实状态与公开状态，死亡可以延后公布；票权独立于生命。提名固定当次门槛，原始选票仅说书人持有；公开投影只有汇总结果。处决事件与死亡分别记录。特殊票数和强制裁定保留原因。

原始导入扩展字段保留在角色 `raw` 和剧本 metadata / extras 中，不解释为可执行脚本，也不渲染为 HTML。JSON 大小、角色数量和字段长度有上限。未知 ID 会保留并标为待补全，而非默默删除。

## 存档策略

日夜切换前自动保存阶段快照，支持手动快照；最多保留最近 8 个。完整存档包含角色、标记、私信、主持笔记与事件，只有说书人能导出。玩家私人的 `bt_notes` 不进入说书人完整魔典。

恢复总是新建房间 ID、房间码和成员关系；不会覆盖原对局。新房间的同一座位会继承该座位历史私信，由说书人在重新绑定玩家前确认恢复用途。公开复盘仅含已批准座位的角色、阵营、生命和自由填写的公开说明。
