## 先了解交付边界

**这些独立文件是从原生图集中拆分整理的，不是 63 张分别独立生成的高清大图。** 不做虚假放大：`manifest.json`、CSV 和预览页列出的都是实际像素。

角色与状态图标大多为 65–137 px，适合当前代码中 26–38 CSS px 的小图标展示。6 张场景为约 200–350 px 宽，适合剧本入口、阶段说明的小缩略图；**不适合直接铺满桌面首页、760 px 魔典座位环或手机全屏背景**。统一卡背为 126 × 178 px，不应当被描述成可无损铺满 340 × 370 px 身份卡的高清素材。

目前没有独立生成的大尺寸无字首页背景、同视角高清昼夜魔典背景、三套剧本的专属高清竖版封面，也没有覆盖全部角色库的专属美术。其余角色可使用类别默认图案，或保留原来的文字徽章。`docs/后续高清素材规格.md` 给出这些缺口的生产规格，**规格不等于已生成文件**。

**模型版本说明：** 本次使用当前会话的图像生成工具；工具返回中没有可独立核验的“image2.5”具体型号标识，因此不将该型号写为已确认。

## 最小接入方式

把本包的 `public/art` 文件夹复制到原项目的 `clocktower/public/art`。单纯复制不会改变网页外观，还需要在组件中引用图片；本包没有修改、覆盖原源码，没有连接 Supabase，没有部署网站。

`integration` 中都是可选接入示例，而非已应用的补丁。先使用角色小图、状态图标、页头小标识；保留现有 Lucide 操作按钮、HTML 文本、键盘交互和现有角色名称。

## 不能从原图照搬的内容

原始图集有生成文字和示例术语，其中存在与源码/游戏实际角色不一致的标签，例如额外的“中立阵营”、泛用人物名称、图标与状态错配等。**原图不是规则文档。** 拆分的独立图标已经去掉原图的角色/状态标签；`manifest.json` 的角色 ID 从上传源码的 `catalog.ts` 对齐，图案只作原创象征，不宣称为官方角色图标。

`fabled` 的星徽也可作“能力已用”装饰，`demon` 复用小恶魔图案，`loric` 复用空白卷轴。复用关系是美术默认值，不是规则等价。幽灵票使用勾/叉时必须同时显示“可用/已用”等文字，不能只凭颜色裁定规则。

## 信息保密

身份卡背必须所有玩家相同，不能按真实角色、阵营、醉毒或存活秘密切换。玩家尚未翻牌时，DOM 和图片 URL 都不应带入其真实角色图。公开城镇也不得新增隐藏身份专属图片或阵营徽章。对玩家可见的角色图案只能依据已有的个人展示身份数据；不能绕开 `personal.role` 等现有展示数据去读取主持人真实魔典。

素材中出现的游戏名称仅说明适用项目；本包不附带官方授权证明，不应被宣传成官方图标库。网站规则、角色能力和操作说明继续由可编辑的正文承载，不能以生成图里的文字代替。
